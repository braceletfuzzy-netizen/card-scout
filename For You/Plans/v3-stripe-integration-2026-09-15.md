# V3 Roadmap: Stripe Integration

## Status
**PARKED — not implementing now.** Captured Sept 15, 2026 after shipping V2 access control.

## Context
Jim said: *"another column we are going to need in the sheets is a confirmation number match that we would get from Stripe once they either pay for the service or log a card. We don't need to implement it just yet but that would allow us to gate and link payment with function"*

## What We Need (V3)

### Schema additions
- `customers.stripe_customer_id` (text, optional) — links to Stripe
- `customers.stripe_subscription_id` (text, optional) — active subscription
- `subscriptions` table (new) — tracks payment events
- `customers.stripe_payment_status` (text) — paid / trial / lapsed
- `form_submissions.stripe_confirmation_number` (text) — returned from Stripe checkout

### Form changes
- New column in Google Sheet: "Stripe Confirmation #" (text, optional)
- Could be:
  - Auto-populated via Stripe Checkout success webhook
  - Manually entered by user
  - Generated by Zapier/Make.com middleware

### Bot logic
- Tier upgrade logic: when confirmation # present → upgrade tier
- Customer portal link: Stripe's hosted billing portal
- Webhook handler: Stripe → /webhook endpoint → DB update
- Customer_id linking: stripe_customer_id maps to our internal customer_id

### Dashboard (V3 dashboard, not V1)
- "Manage subscription" button → redirects to Stripe portal
- "View invoices" button → shows Stripe history
- "Upgrade/downgrade" buttons → opens Stripe Checkout

## Architecture Pattern

```
Customer fills form → Stripe Checkout → Stripe webhook → DB update → bot activation
                      ↓
              Stripe confirmation # → form (or auto-populate)
                      ↓
              Bot imports customer + tier=paid if confirmation # present
```

## Decision Points (when we get there)

1. **Self-serve vs. assisted billing?**
   - Self-serve: Stripe Checkout hosted, customer manages own subscription
   - Assisted: you send Stripe links manually, confirm payment in DB

2. **Tier structure?**
   - Currently: trial (3 cards), beta_power (?), paid (?)
   - Need to define what each tier costs

3. **Webhook endpoint hosting?**
   - Local Flask app (current dashboard) — works for dev
   - Hetzner VPS (when deployed) — works for production
   - Stripe CLI for testing

4. **Failure modes?**
   - Customer pays but webhook never arrives → manual reconcile
   - Customer cancels → bot stops alerting at end of period
   - Customer refunds → tier downgraded

## Cost Estimate (V3 work)

- Stripe integration: ~$0/mo (no Stripe fee on free tier, 2.9% + 30¢ on charges)
- Webhook endpoint: $0/mo (uses existing dashboard)
- Time to implement: ~6 hours (when we have paying customers)

## Why V3, Not V2

V2 = dashboard + listing filter (already shipped Sept 15)
V3 = Stripe integration + payment gating

Don't ship payment complexity until you have:
- 5+ paying customers (need to validate the model first)
- Clear pricing (need to know what we're charging for)
- Time to support billing questions

## When to Implement

Triggers (in order of priority):
1. First paying customer manually (set up Stripe, accept payment outside the system)
2. 5+ manual payments → "this is too much manual work, automate"
3. Customer churn / refund requests → need automated billing
4. $100+/mo revenue → can afford to spend 6 hours on integration

For now (Sept 15, 2026): Jim is beta, not paying, doesn't need Stripe.
